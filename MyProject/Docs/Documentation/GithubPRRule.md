# Github PR 작성 규칙

> Github Pull Request를 작성할 때의 규칙
>
> PR 작성 양식은 `Docs/Template/PRTemplate.md`를 참고.
>
> 해당 문서는 각 섹션에 대한 작성 규칙을 정의한다.

## 1. Title

- `[말머리] 작업 내용 요약` 형태로, 명사형으로 적는다.
- 말머리는 연결된 Issue의 Label을 기준으로 `Docs/Documentation/GithubIssueRule.md` `7. 기타`의 대응표에서 정한다.
- 연결된 Issue가 없으면 대응표의 `용도`를 보고 작업 내용에 맞는 말머리를 선택한다.

- 예시 :

    ```markdown
    - [Feat] 플레이어 점프 기능 추가
    - [Fix] 키입력 미동작 수정
    - [Docs] PR 작성 규칙 추가
    ```

## 2. 연결 Issue

- DoD 충족 여부는 PR 생성 직전에 한 번 판정한다. (`github-pr` 스킬 `1. 정보 수집`)
  - Claude 확인 항목은 `ClaudeCodeRules.md` `행동 원칙 > 1. 사고 우선 (Think Before Coding)`의 `검증` 또는 `코드 확인` 등급이면 충족으로 본다. `미검증`이면 사용자에게 확인을 요청한다.
  - `(사용자 확인)` 항목은 사용자에게 묻고, `확인함` 답을 받으면 충족으로 본다. 동작이나 에디터 결과를 봐야 하는 항목에 `(사용자 확인)`을 붙이는 규칙은 `GithubIssueRule.md` `5. 완료조건 (DoD)`를 따른다.
- DoD를 모두 충족하면 `Closes #번호`로 적는다. 병합 시 해당 Issue가 자동으로 닫힌다.
- 충족하지 못한 항목이 있으면 `Refs #번호`로 적는다. Issue는 자동으로 닫히지 않는다. (`WorkflowRules.md` `11. Issue Close`)
- 연결된 Issue가 여러 개면 한 줄에 하나씩 적는다.
- Issue가 없는 업무는 "없음"으로 적는다.

- 예시 :

    ```markdown
    ## 연결 Issue
    - Closes #12
    ```

## 3. 작업 내용

- 해당 브랜치의 변경 사항을 항목별로 기록한다.
  - 명사형 종결을 권장한다. (`~추가`, `~수정`, `~제거`)
  - 한 항목에는 하나의 변경만 적는다.
  - `대상 : 변경 내용 (방법)` 형태로, 무엇을 / 어디에 / 어떻게 했는지 드러나게 적는다.

- 예시 :

    ```markdown
    ## 작업 내용
    - `PlayerJump.cs` 생성 : 스페이스바 입력 시 점프 (InputActionReference 사용)
    - 점프 조건 추가 : 지면 접촉 시에만 점프 가능
    - 지면 판정 추가 : 발밑 Raycast로 지면 여부 확인
    ```

## 4. 확인 사항

- Claude는 자신이 확인한 항목만 체크한다. (`관계없는 파일`은 `git diff`로 확인한다)
- 콘솔 에러 항목은 Unity MCP가 켬이면 PR 생성 직전에 메인이 다시 조회해 `검증` 등급이면 Claude가 체크한다. (`Docs/Claude/ClaudeCodeRules.md` `Unity MCP 사용 규칙 > 검증 등급`)
- 사용자 확인 항목(Unity 실행 테스트, `검증` 등급이 아닌 콘솔 에러)은 사용자가 `확인함`이라고 답한 경우에만 체크하고 줄 끝에 `(사용자 확인함)`을 붙인다. 답이 없으면 체크하지 않는다.
- 해당되지 않는 항목은 체크하지 않고 줄 끝에 `(해당 없음)`을 적는다.
- 씬 소유자 항목은 `Docs/TechSpec.md` `1. 프로젝트 제원`의 팀 구성이 1인이면 `(해당 없음)`이고, 팀이면 사용자 확인 항목으로 다룬다.

- 예시 :

    ```markdown
    ## 확인 사항
    - [x] Unity에서 실행 테스트해 보았다. (사용자 확인함)
    - [x] 콘솔에 에러가 없다. (사용자 확인함)
    - [x] 관계없는 파일이 같이 들어가지 않았다.
    - [ ] 씬 파일이 들어갔다면 내가 그 씬의 소유자이다. (해당 없음)
    - [x] 연결된 Issue의 완료조건(DoD)을 모두 충족했다.
    ```

## 5. 화면

- 동작을 눈으로 확인해야 하는 작업이면 참고용 이미지나 영상을 첨부한다.
- 필요하지 않으면 "불필요"로 적는다.

## 6. 참고사항

- 변경되었거나, 리뷰 시 중요하게 봐야 할 파일의 경로를 적는다.

- 예시 :

    ```markdown
    ## 참고사항
    - `Assets/Scripts/Player/PlayerJump.cs`
    - `Assets/Prefabs/Player/Player.prefab`
    ```

## 7. 특이사항

- 전달사항 및 우려사항이 있는 경우에만 기재한다. 없으면 "없음"으로 적는다.
