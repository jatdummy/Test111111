# Github Branch 작성 규칙

> Github 브랜치를 생성하고 관리할 때의 규칙
>
> 브랜치의 생성 / 삭제 주체는 `Docs/Claude/WorkflowRules.md` `0. 전체 흐름 > 역할 구분`을 따른다.
>
> 해당 문서는 기준 브랜치와 브랜치 이름에 대한 규칙을 정의한다.

## 1. 기준 브랜치

- 작업 브랜치는 기준 브랜치에서 생성한다.
- PR 대상 브랜치는 기준 브랜치로 한다.
- 기준 브랜치와 보호 브랜치는 `Docs/TechSpec.md` `4. 워크플로우 설정`을 따른다. (기본값 : `main`)
- 보호 브랜치에서는 직접 작업하지 않는다. (`CLAUDE.md` 절대 원칙 1)
- 작업 브랜치를 만들기 전에 기준 브랜치를 `pull --ff-only`로 최신 상태로 맞춘다.
- Develop 브랜치를 쓰는 경우, Develop에서 main으로 반영하는 릴리스 PR은 사용자가 수행하며 병합 방식은 `merge`를 권장한다. (squash를 쓰면 두 브랜치의 이력이 갈라진다)

## 2. 이름 형식

- `[접두사]/[이슈번호]-[작업명]` 형태로 적는다.
  - 접두사 : `Docs/Documentation/GithubIssueRule.md` `7. 기타` 대응표의 `브랜치 접두사` 열을 사용한다.
  - 작업명 : 영어 소문자로 적고, 단어 사이는 `-`로 구분한다.
- Issue가 없는 작업은 이슈번호를 생략한다.

- 예시 :

    ```
    feat/12-player-jump
    fix/15-key-input
    docs/pr-rule
    ```

## 3. 임시 브랜치

- 테스트용 임시 브랜치는 `test/[작업명]` 형태로 생성한다.
- 임시 브랜치는 PR 대상이 아니며, 사용이 끝나면 삭제한다.

- 예시 :

    ```
    test/skill-check
    ```
